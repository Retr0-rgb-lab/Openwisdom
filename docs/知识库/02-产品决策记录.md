## 1. 产品形态

**选择：** 网页形态 + 开源 GitHub 仓库。

- 仓库包含不同 skill  
- 用户可在网页下载，也可在 GitHub 下载  
- 开放社区，用户可增加 skills  

**否决/搁置：** 纯 skills 库无官网、纯在线分析台作为 v1 核心。

---

## 2. 网页：技能目录站

**选择：** 目录站（非在线分析台）。

用户主路径：

```
浏览/搜索 skill → 阅读说明 → 下载或复制安装命令
        → 在自己的 Agent 中运行分析
```

网页提供中英界面切换；不负责托管用户的对话会话。

---

## 3. CLI：技能包管理器（方案 A）

**选择：** 只做包管理，不做分析运行时。

预期能力（v1）：

| 命令意图 | 说明 |
|----------|------|
| `search` | 搜索可安装 skill / reference |
| `install` | 安装到用户选择的 Agent 目录 |
| `update` | 更新已安装内容 |
| `list` | 列出可用或已安装项 |

**明确不做：** `run <skill> "..."` 自带 API 调用出报告。

---

## 4. 多 Agent 适配（Impeccable 模式）

**选择：** 像 Impeccable CLI 一样，适配当前几乎所有主流 coding agent；下载/安装后在终端**交互选择**为哪些 harness 安装。

参考能力（来自 Impeccable 生态，作为实现参照而非绑定）：

- 检测本机/项目中已有的 harness 目录  
- 交互多选 providers（或 `-y --providers=...` 非交互）  
- project / global scope  
- 统一源格式 → 写入各 provider 约定路径  

已知常见 provider 目录名（实现阶段再固化清单）：

`.claude`、`.cursor`、`.agents`（Codex）、`.github`（Copilot）、`.gemini`、`.grok`、`.opencode`、`.pi`、`.kiro`、`.qoder`、`.trae` / `.trae-cn`、`.rovodev`、`.vibe` 等。

---

## 5. Skill 内容架构（方案 D）

**两层模型：**

```
┌─────────────────────────────────────────┐
│  场景 Skills（可调用流程）                 │
│  · macro-scan（宏观扫描）                 │
│  · personal-anchor（个人锚点）            │
│  · metacognition-audit（元认知体检）      │
└─────────────────┬───────────────────────┘
                  │ 引用
                  ▼
┌─────────────────────────────────────────┐
│  学科 References（理论/方法卡片）          │
│  心理学 · 社会学 · 历史学 · 政治学 · 经济学 │
│  例：前景理论、精英理论、路径依赖…         │
└─────────────────────────────────────────┘
```

| 层级 | 职责 | 用户心智 |
|------|------|----------|
| 场景 skill | 规定提问流程、输出结构、调用哪些 reference、反偏见检查点 | 「帮我做一件事」 |
| Reference | 单个理论/方法的定义、适用边界、常见误用、引导问题 | 「给我一块可引用的知识积木」 |

**否决倾向：** 仅五大巨型学科 skill（难贡献、难组合）；仅原子理论而无场景（难直接达成产品目标）。

## 6. 语言策略

| 层级 | 策略 |
|------|------|
| 网页 UI | 中 / 英切换 |
| Skill / reference 正文 | 以贡献者上传语言为准，不强制双语全文 |
| 元数据 | 建议包含：`id`、名称、摘要、语言代码（`zh`/`en`/…）、学科标签、层级（scenario/reference）、official|community 等，便于目录检索 |

---

## 7. 社区与仓库分层（B + D）

**B — 贡献路径**

- 合入真相源：**GitHub PR**  
- 网页：**贡献页**（规范说明、模板链接、Issue/PR 模板跳转）  
- v1 **不做**网页表单直传 + 自建审核后台  

**D — 目录分层**

| 分区 | 含义 | 合入门槛（原则） |
|------|------|------------------|
| `official/` | 核心维护、与产品叙事强绑定 | 较高：质量、风格、可引用性 |
| `community/` | 社区贡献 | 较低但仍需规范与基础审查 |

网页可筛选 official / community；展示质量/来源徽章。

## 9. 首页信息架构（方案 C）

**双心智：**

1. **默认落地页（产品叙事）**  
   - Hero：宏观分析 / 历史锚点 / 元认知  
   - 多 harness 兼容展示  
   - 安装路径（CLI 一命令为主）  
   - 三大场景 skill 能力展示  
   - 链向完整目录与贡献  

2. **Skills 目录（图书馆）**  
   - 主导航显眼入口  
   - 场景 / 学科 / 语言 / official·community 筛选与搜索  
   - 详情页：说明、标签、下载、安装命令  

常驻：Docs、Contribute、GitHub、语言切换。

## 11. Skill 热度 / 下载量（第三档）

**选择：** 同时记录 **网页侧行为** 与 **CLI 安装成功**，作为 skill 热度。

| 计入「安装热度」主指标 | 权重 / 说明 |
|------------------------|-------------|
| CLI `install` **成功写入** Agent 目录后 | **主计数**（+1 / skill / 成功安装事件） |
| 网页 **下载 zip / 打包下载** 成功发起 | **主计数**（与 CLI 同榜或分项展示 installs） |
| 网页 **复制安装命令** | **次级 / 低权重** 或不计入主榜（可记 `copy` 事件供漏斗，默认不驱动 `sort=popular`） |
| 仅打开详情页 | **不计入** 下载/安装热度（可另做 pageview，非 v1 必须） |

**原则：**

- **匿名**：只记 `skillId`、事件类型、日桶、可选粗粒度渠道（web|cli）；不登录、不存可识别个人信息  
- **可退出**：CLI 支持 `--no-telemetry` / 环境变量关闭；隐私说明写在 Docs/FAQ  
- **防误导**：展示优先 **近 30 天** + 累计；文案用「安装热度 / Installs」，避免与 GitHub Download 混淆  
- **排序**：默认仍 **featured**；用户可选 `sort=popular`  
- **数据位置**：热度 **不写进** `SKILL.md`；由统计服务维护，经 API/`stats` 合并进目录展示  
- **GitHub 直接 clone/raw**：v1 **不强求**计入（测不准）；以官网与官方 CLI 为准  

**否决：** 仅展示假热度、或 v1 完全不做计数（已升级为要做第三档）。

详细管道见 `docs/specs/01-架构方案.md` § 热度统计、`docs/specs/06-热度与遥测.md`。
