# 文档治理与规格分层

> **更新：** 2026-07-31  
> **目的：** 单一权威、渐进披露；避免「半活 specs + 半活知识库」漂移。

---

## 1. 当前三层（specs 已退役）

| 层 | 路径 | 写什么 | 不写什么 |
|----|------|--------|----------|
| **L0 产品真相** | `PRODUCT.md` · `DESIGN.md` · `AGENTS.md` | 用户、非目标、品牌硬规则、Agent 入口 | 逐文件实现任务、过期调研全文 |
| **L1 知识库（权威）** | `docs/知识库/` | **决策、现状、实现契约**（架构/IA/视觉/Skills/CLI·MCP/热度/交接层） | 按日 checklist、一次性整改日记 |
| **L2 过程** | `docs/plans/` | 按日 plan、wave report、VERIFY | 当作「当前契约权威」阅读 |

**已退役：** `docs/specs/` 及其 `archive/`。原活规格内容已蒸馏进知识库 **07–14**。  
历史调研若需溯源，只在 git 历史或 plans 中查找，**不**再作为实现权威。

**冲突时：**

1. 用户当轮指令  
2. `PRODUCT.md` + 知识库 **02** 决策  
3. 知识库专题文（07–14）+ `DESIGN.md`（视觉）  
4. `docs/plans/*`（过程意图）

视觉 token：`DESIGN.md` + 知识库 **09** **>** 旧铜 Direction B。

## 2. Progressive disclosure（给 Agent）

| 层 | 何时加载 | 内容 |
|----|----------|------|
| **L0** | 每任务 | `AGENTS.md` 身份 + 硬规则 + 本篇任务路由 |
| **L1** | 已知任务类型后 | **只打开知识库一篇**（见 [00-索引](./00-索引.md) 任务表） |
| **L2** | 实现该区域时 | 代码路径 + 必要时 `docs/plans/YYYY-MM-DD-*/` |
| **L3** | 罕见 | 全库审计、git 历史 SPE |

**禁止** 每次 bulk 读全部知识库或整棵 `docs/`。

## 4. 写入规则

1. **新决策** → 只 **追加** `02` 修订日志与总表，勿静默改写无痕迹。  
2. **契约变更** → 改对应 07–14 正文，并在 `05` 同步现状若已实现。  
3. **执行波次** → 只放 `docs/plans/`，完成后可在 `05` 勾残差，**不**回灌成第二套 SPE 树。  
4. **不要** 再创建 `docs/specs/*`。  
5. 内部链接一律相对路径指向 `docs/知识库/` 或仓库根 `PRODUCT.md` / `DESIGN.md`。

---

## 5. Agent 阅读顺序

1. `AGENTS.md` L0  
2. 知识库 **05**（是否已实现）  
3. 任务对应 **单篇** 07–14  
4. 若在执行中：`docs/plans/*`  
5. 改 UI：`DESIGN.md` + **09** + `apps/web` 消息文件
