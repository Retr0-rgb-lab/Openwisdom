# Openwisdom 架构方案 Spec

> 状态：草案（待拍板）  
> 日期：2026-07-29  
> 调研依据：Impeccable monorepo/CLI 模式、skills.sh / Agent Skills、shadcn registry、Fumadocs、pnpm+Turbo、Content Collections vs Contentlayer

---

## 1. 架构目标

| 目标 | 约束 |
|------|------|
| Skills 可被网页发现与下载 | GitHub 为内容真相源 |
| CLI 安装到多 Agent | 与 Web 共用同一索引，禁止元数据漂移 |
| 双语 UI | 站点 UI 中/英；skill 正文随贡献语言 |
| 成熟产品站 | 自定义营销+目录，不是纯文档皮肤 |
| 开源贡献 | `official/` + `community/`；PR 合入 |
| v1 可运维 | Vercel 部署 Web；npm 发布 CLI |

---

## 2. 三套方案对比

### 方案 A — 索引中心 monorepo（**推荐**）

```text
skills/**/SKILL.md
        │
        ▼
 packages/catalog  ──► catalog.json
        │                  │
        │                  ├──► apps/web (SSG 目录/详情)
        │                  ├──► public/registry/* (机器可读)
        │                  └──► packages/cli (bundle + 可远程刷新)
        └── 安装时从 GitHub 拉取 skill 目录内容
```

| 优点 | 缺点 |
|------|------|
| Web / CLI / GitHub 元数据一致 | 需维护小型 catalog 构建器 |
| 可做 Impeccable 级自定义官网 | 包比单仓稍多 |
| 兼容 Agent Skills 目录习惯 | 多 Agent 安装逻辑要认真做 |
| CI 可校验 skill 引用完整性 | |

**适用：** 当前 v1 完整目标（成熟站 + 多 skill 库 + CLI）。

---

### 方案 B — Fumadocs / 文档站为主 + 侧挂目录

以文档框架为壳，目录列表是「带筛选的文档集合」。

| 优点 | 缺点 |
|------|------|
| Docs/i18n/搜索默认能力快 | 叙事落地页与「产品官网」气质难做满 |
| MD 管道现成 | 多维筛选（official/community/学科）易像补丁 |
| | 与 impeccable 成熟度对标更吃力 |

**适用：** 刻意降低营销野心、内容远重于品牌时。

---

### 方案 C — 多仓拆分（skills / site / cli）

Impeccable 后期方向：内容与 CLI 一仓，营销站另仓。

| 优点 | 缺点 |
|------|------|
| 站点迭代独立 | **漂移**与同步成本高（违背「官网与仓库一致」） |
| | 贡献者无法一次 PR 闭环 |
| | 开源故事弱 |

**适用：** 仅 post-v1 若站点需私有分析/CMS。**v1 不推荐。**

---

### 排名

| 排名 | 方案 | 结论 |
|------|------|------|
| 1 | **A 索引中心 monorepo** | **默认采用** |
| 2 | B 文档站为主 | 备选降级 |
| 3 | C 多仓 | v1 排除 |

## 3. 推荐 monorepo 布局（方案 A）

```text
Openwisdom/
├── apps/
│   └── web/                 # Next.js：官网 + 目录 + docs
├── packages/
│   ├── cli/                 # npm: openwisdom（包名以注册为准）
│   ├── catalog/             # 扫描 skills → catalog.json
│   ├── schema/              # zod：frontmatter + 索引 schema
│   ├── providers/           # Agent 路径表（claude/cursor/codex/…）
│   └── ui/                  # 可选：Web 设计系统组件
├── skills/                  # ★ 内容真相源
│   ├── official/
│   │   ├── scenarios/
│   │   │   ├── macro-scan/
│   │   │   ├── personal-anchor/
│   │   │   └── metacognition-audit/
│   │   └── references/
│   │       ├── psychology/
│   │       ├── sociology/
│   │       ├── history/
│   │       ├── political-science/
│   │       └── economics/
│   └── community/
│       ├── scenarios/
│       └── references/
├── docs/                    # 内部知识库/specs（本目录）— 非站点
├── scripts/
├── pnpm-workspace.yaml
├── turbo.json
└── .github/workflows/
```

**原则：** 不在 monorepo 根复制多份 `.claude/.cursor` 技能树；安装时由 CLI 写入用户环境。仓库内只保留**源格式** skills。

## 4. Skill 单元与元数据

```text
skills/official/scenarios/macro-scan/
├── SKILL.md
└── assets/          # 可选
```

**Frontmatter（最小集，`packages/schema` 校验）：**

| 字段 | 说明 |
|------|------|
| `id` | 稳定 slug |
| `name` | 展示/Agent 名 |
| `description` | 一句话（目录 + Agent 发现） |
| `layer` | `scenario` \| `reference` |
| `discipline` | 五学科之一或 null（场景可多学科用 tags） |
| `disciplines` | 可选数组 |
| `scope` | `official` \| `community` |
| `language` | 正文语言 `zh` / `en` / … |
| `tags` | 字符串数组 |
| `version` | semver |
| `references` | 场景引用的 reference id 列表 |
| `updated` | ISO 日期（可生成） |

兼容 Agent Skills 生态常见的 `name` + `description` 最小字段，便于 `npx skills add …` 作为次要安装路径。

## 5. 内容管道（防漂移）

```text
skills/**/SKILL.md
    → packages/catalog build
    → dist/catalog.json
    → dist/manifest.json  (gitSha, generatedAt, contentHash)
    → apps/web 构建导入 + 复制到 public/registry/
    → packages/cli 发布时打包快照；运行时可 fetch 生产 registry
```

| 消费者 | 行为 |
|--------|------|
| Web 目录/详情 | **构建时**读 monorepo skills + catalog.json（SSG） |
| `/registry/catalog.json` | 静态机器索引（类 shadcn registry） |
| CLI search/list | 优先本地快照；`update`/联网可刷新远程索引 |
| CLI install | 按 catalog 路径从 **GitHub** 拉 skill 目录写入各 Agent |
| Zip 下载 | CI/Release 或构建生成，不把大二进制塞进 git |

**铁律：** 站点不得发明不在 `skills/**` 或其生成物中的 skill 元数据。

**工具选择：** 自研 `packages/catalog`（gray-matter + zod）。**不使用 Contentlayer**（维护停滞、App Router 体验差）。Docs 可用 Fumadocs MDX 或 Content Collections。

## 6. Web 技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **Next.js App Router** | RSC、SSG、Vercel 友好 |
| 目录 UI | **自定义页面** | 多维筛选 + 产品级落地，非纯 docs 主题 |
| Docs | **Fumadocs（headless）** 或 Sidebar+MDX | 文档嵌在产品站内 |
| 样式 | **Tailwind CSS v4** + CSS variables | 对接 shadcn |
| 组件 | **shadcn/ui** | 见 `04-组件与动效` |
| 动效点缀 | **React Bits**（拷贝/注册表引入） | 见 `04` |
| i18n | **next-intl** | `/zh` `/en` UI |
| 主题 | **next-themes** | light-first + dark |
| Markdown | react-markdown / MDX + Shiki | skill 正文、docs |

**路由（locale 前缀）：**

```text
/[locale]/                     # 叙事首页
/[locale]/skills               # 目录
/[locale]/skills/[slug]        # 详情（scenario 与 reference 统一）
/[locale]/install              # 安装中枢
/[locale]/docs/*               # 文档
/[locale]/contribute
/[locale]/about
/[locale]/disciplines[/*]      # P1
/registry/catalog.json          # 无 locale
```

## 7. CLI 技术栈

| 项 | 选型 |
|----|------|
| 语言 | TypeScript ESM，Node ≥ 20（可对齐生态 ≥22） |
| 交互 | **@clack/prompts**（多选 Agent，类 Impeccable） |
| 框架 | citty 或 commander |
| 能力 v1 | `search` / `install` / `update` / `list` |
| 安装 UX | 检测 harness → 交互多选 providers → project|global → 写入路径 |
| 标志 | `--providers`、`--scope`、`-y`、`--force` |
| 分发 | npm bin：`npx openwisdom …` |
| **不做** | 调用 LLM / `run` 分析 |

**Provider 包（`packages/providers`）** 维护路径表，参考 Impeccable / skills 生态：

`.claude`、`.cursor`、`.agents`（Codex）、`.github`、`.gemini`、`.grok`、`.opencode`、`.pi`、`.kiro`、`.qoder`、`.trae`/`.trae-cn`、`.rovodev`、`.vibe` 等；特殊全局路径（如 OpenCode config dir、Pi `~/.pi/agent/skills`）单独表项。

## 8. i18n 策略

| 层 | 策略 |
|----|------|
| UI | `messages/zh.json` + `messages/en.json`；路由 `/zh` `/en` |
| Skill 正文 | 单文件单语言，`language` 字段；目录可筛 |
| 核心 Docs | v1 提供中英 UI 壳 + 核心文档双语（Getting started / FAQ / Spec 摘要） |
| SEO | hreflang、分 locale title/description |
| CLI | 关键提示可中英；默认跟随环境或 `--lang` |

## 9. 部署与 CI

```text
PR / main:
  install → validate skills (schema, unique id, broken refs)
  → turbo build/test (catalog, cli, web)
  → Vercel preview (web)

tag v*:
  同上 + npm publish cli + 可选 GitHub Release / official zip
```

| 目标 | 平台 |
|------|------|
| Web | **Vercel**，root monorepo，filter `apps/web` |
| CLI | **npm** |
| 内容 | **GitHub** |

## 10. 热度统计（v1：网页 + CLI）

> 产品决策 #11：第三档。细则见 [06-热度与遥测.md](./06-热度与遥测.md)。

### 10.1 目标

- 每个 skill 可展示 **安装热度**（累计 + 近 30 天）  
- 目录支持 `sort=popular`  
- 不引入用户账号  

### 10.2 管道概览

```text
Web: 下载 zip 成功 ──┐
Web: 复制命令(次级) ──┼──► POST /api/telemetry  ──► 统计存储(KV/DB)
CLI: install 成功  ──┘         │
                               ▼
                    聚合 → GET /api/stats 或 /registry/stats.json
                               │
                               ▼
                    目录/详情合并展示 installs30d / installsTotal
```

| 组件 | 职责 |
|------|------|
| `apps/web` Route Handlers | 接收匿名事件、限流、写库；对外只读 stats |
| 统计存储 | Vercel KV / Upstash Redis / SQLite·Turso 等（实现选型见 06） |
| CLI | install 成功后 fire-and-forget 上报；失败不影响安装退出码 |
| catalog 构建 | **不**内嵌热度；运行时或 ISR 合并 stats |

### 10.3 与「纯静态」的关系

方案 A 仍以 skills git 为内容真相源；热度是 **旁路服务**。无统计服务时：站点降级为不显示数字 / 不提供 popular 排序，内容浏览不受损。

### 10.4 实现顺序中的位置

与 Web InstallCommand、CLI install **同一阶段接入**（非 post-v1 纯预留）。

## 11. 实现顺序（架构视角）

1. Monorepo 脚手架 + schema + 示例 official scenario  
2. catalog 构建与校验  
3. CLI install（先 2–3 个 provider，再扩表）+ **成功遥测**  
4. Web：首页 + 目录 + 详情 + InstallCommand + **telemetry/stats API**  
5. next-intl + contribute/docs + 隐私/FAQ 说明  
6. CI + Vercel + npm
