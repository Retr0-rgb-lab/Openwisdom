# 文档治理与规格分层

> **更新：** 2026-07-30  
> **目的：** 避免 specs 无限膨胀；决策进知识库，执行进活 specs，过程进 archive/plans。

---

## 1. 三层文档

| 层 | 路径 | 写什么 | 不写什么 |
|----|------|--------|----------|
| **L0 产品真相** | `PRODUCT.md` · `DESIGN.md` · `AGENTS.md` · `docs/知识库/` | 用户、非目标、拍板决策、现状地图、验收直觉 | 逐文件实现任务、过期调研全文 |
| **L1 活规格** | `docs/specs/`（非 archive） | **仍指导实现或仍被引用** 的契约：架构、IA、热度 API、CLI/MCP 行为 | 已执行完毕的整改日记、重复调研 |
| **L2 过程与归档** | `docs/specs/archive/` · `docs/plans/` | 历史 SPE、调研纪要、审计快照、按日 plan/report | 当作「当前权威」阅读 |

**冲突时：** PRODUCT + 知识库决策 **>** 活 specs **>** archive。视觉 token：`DESIGN.md` + Spec 07/08 **>** 旧铜方向。

---

## 2. Specs 清理原则（2026-07-30）

1. **归档：** 被 supersede 的视觉草案、调研纪要、英文 IA dump、Home 动效调研、一次性 SPE 总控过程稿、审计全文快照。  
2. **保留活规格：** 架构、IA、品牌/动效权威摘要、Skills/CLI/MCP 契约、热度产品决策(06)、**热度 API 实现(27–29)**。  
3. **知识库沉淀：** 审计结论与「现状地图」进 `05`；治理进本篇；新决策只 **追加** `02` 修订日志。  
4. **Plans 不进 specs：** 实现步骤只放 `docs/plans/YYYY-MM-DD-*/`。
