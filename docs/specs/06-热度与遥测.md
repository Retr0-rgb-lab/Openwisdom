## 1. 目标

| 目标 | 说明 |
|------|------|
| 热度信号 | 每个 skill 有可展示的安装/下载热度 |
| 双端采集 | **网页** + **CLI 安装成功** |
| 无账号 | 匿名、聚合、可退出 |
| 不污染内容库 | 统计数据不进入 `SKILL.md` / git skills 树 |

**非目标：** 用户级画像、广告追踪、强制联网才能安装、精确到个人的安装历史。

---

## 2. 事件模型

### 2.1 事件类型

| `event` | 来源 | 是否计入主热度 `installs*` | 说明 |
|---------|------|---------------------------|------|
| `cli_install_success` | CLI | **是**（权重 1） | 文件成功写入所选 provider 之后 |
| `web_download` | Web | **是**（权重 1） | zip/打包下载成功触发（或 signed URL 发放成功） |
| `web_copy_install` | Web | **否**（仅漏斗） | 复制 `npx openwisdom install …` |
| `web_view`（可选） | Web | 否 | v1 可不做 |

同一 skill 装到多个 provider 的一次 CLI 交互：  
**推荐计 1 次** `cli_install_success`（按 skill，不按 provider 倍增），payload 可带 `providerCount`。

### 2.2 上报 payload（匿名）

```json
{
  "schemaVersion": 1,
  "event": "cli_install_success",
  "skillId": "macro-scan",
  "ts": "2026-07-29T12:00:00.000Z",
  "source": "cli",
  "cliVersion": "0.1.0",
  "sessionId": "optional-random-uuid-per-invocation",
  "meta": {
    "providers": ["claude", "cursor"],
    "scope": "global"
  }
}
```

| 字段 | 要求 |
|------|------|
| **禁止** | 姓名、邮箱、机器名、完整主目录路径、IP 入库长期画像（边缘限流可用 IP，**不写入统计明细展示**） |
| `sessionId` | 可选，仅用于短时去重（如 5 分钟内同一 skill 重复点击），可哈希 |
| `skillId` | 必须已存在于 catalog（服务端校验，拒收未知 id 防刷垃圾键） |

### 2.3 聚合指标（对外）

```json
{
  "macro-scan": {
    "installsTotal": 1234,
    "installs30d": 56,
    "downloadsTotal": 800,
    "downloads30d": 40,
    "cliInstallsTotal": 434,
    "cliInstalls30d": 16,
    "updatedAt": "…"
  }
}
```

**主排序键：** `installs30d` =（加权）`cli_install_success` + `web_download` 近 30 天。  
**展示文案（i18n）：** 「安装热度」「Installs (30d)」；详情可展开 CLI / Web 分项（P1，v1 可只显示合计）。

## 3. 采集点

### 3.1 Web

| 动作 | 实现要点 |
|------|----------|
| 下载 | 下载按钮 handler：开始下载后 `navigator.sendBeacon` / `fetch` keepalive POST |
| 复制安装命令 | 复制成功 toast 时上报 `web_copy_install`（**不进主榜**） |
| 失败 | 上报失败不阻断 UI |

### 3.2 CLI

| 动作 | 实现要点 |
|------|----------|
| 时机 | **全部**目标 provider 写入成功（或用户选中的集合已成功）之后 |
| 方式 | 异步 HTTP，**短超时**（如 800ms–1.5s），失败静默 |
| 关闭 | `--no-telemetry`、`OPENWISDOM_NO_TELEMETRY=1`、配置文件 `telemetry: false` |
| 首次提示 | 可选：首次 install 打印一行「将匿名上报安装热度；--no-telemetry 可关闭」（勿交互阻断 CI） |
| CI | 检测 `CI=true` 时可默认关闭遥测，避免刷量 |

## 4. API 表面

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/telemetry` | POST | 接收事件；校验 schema + skillId；限流 |
| `/api/stats` 或 `/registry/stats.json` | GET | 只读聚合；可 CDN 缓存 5–15 分钟 |
| （可选）`/api/stats?ids=a,b` | GET | 批量查询，供目录页 |

**限流（示例）：** 同 IP 60 事件/分钟；同 skill+IP 同事件 10/小时（防刷）。超限 429，客户端忽略。

---

## 5. 存储选型（实现时定一）

| 选项 | 适合 |
|------|------|
| **Upstash Redis / Vercel KV** | 计数 INCR、日桶 key、无服务器友好（**推荐默认**） |
| Turso / PlanetScale | 需更复杂查询、管理后台时 |
| 纯日志 + 定期聚合 | 更重运维，非 v1 首选 |

**日桶 key 示例：** `ow:evt:{yyyy-mm-dd}:{skillId}:{event}` → 定期 rollup 到 total/30d。

---

## 6. 前端合并策略

1. 目录页加载 `catalog`（静态）+ `stats`（SWR/ISR fetch）  
2. 合并到 SkillCard：`installs30d`  
3. stats 失败：不显示数字，排序 popular 回退 featured 或 name  
4. **永不**因遥测失败阻塞安装或下载

## 8. 反作弊（务实 v1）

| 手段 | v1 |
|------|-----|
| skillId 白名单 | 必须 |
| 限流 | 必须 |
| CI 默认关遥测 | 必须 |
| 复制命令不进主榜 | 必须 |
| 验证码 / 登录 | 不做 |
| 异常暴增人工打压 | 运维手册级，可选 |
