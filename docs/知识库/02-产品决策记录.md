## 1. 产品形态

**选择：** 网页形态 + 开源 GitHub 仓库。

- 仓库包含不同 skill  
- 用户可在网页下载，也可在 GitHub 下载  
- 开放社区，用户可增加 skills  

**否决/搁置：** 纯 skills 库无官网、纯在线分析台作为 v1 核心。

---

## 2. 网页：技能目录站

**选择：** 目录站（非在线分析台）。

用户主路径：

```
浏览/搜索 skill → 阅读说明 → 下载或复制安装命令
        → 在自己的 Agent 中运行分析
```

网页提供中英界面切换；不负责托管用户的对话会话。

---

## 3. CLI：技能包管理器（方案 A）

**选择：** 只做包管理，不做分析运行时。

预期能力（v1）：

| 命令意图 | 说明 |
|----------|------|
| `search` | 搜索可安装 skill / reference |
| `install` | 安装到用户选择的 Agent 目录 |
| `update` | 更新已安装内容 |
| `list` | 列出可用或已安装项 |

**明确不做：** `run <skill> "..."` 自带 API 调用出报告。

---

## 4. 多 Agent 适配（Impeccable 模式）

**选择：** 像 Impeccable CLI 一样，适配当前几乎所有主流 coding agent；下载/安装后在终端**交互选择**为哪些 harness 安装。

参考能力（来自 Impeccable 生态，作为实现参照而非绑定）：

- 检测本机/项目中已有的 harness 目录  
- 交互多选 providers（或 `-y --providers=...` 非交互）  
- project / global scope  
- 统一源格式 → 写入各 provider 约定路径  

已知常见 provider 目录名（实现阶段再固化清单）：

`.claude`、`.cursor`、`.agents`（Codex）、`.github`（Copilot）、`.gemini`、`.grok`、`.opencode`、`.pi`、`.kiro`、`.qoder`、`.trae` / `.trae-cn`、`.rovodev`、`.vibe` 等。

## 5. Skill 内容架构（方案 D）

**两层模型：**

```
┌─────────────────────────────────────────┐
│  场景 Skills（可调用流程）                 │
│  · macro-scan（宏观扫描）                 │
│  · personal-anchor（个人锚点）            │
│  · metacognition-audit（元认知体检）      │
└─────────────────┬───────────────────────┘
                  │ 引用
                  ▼
┌─────────────────────────────────────────┐
│  学科 References（理论/方法卡片）          │
│  心理学 · 社会学 · 历史学 · 政治学 · 经济学 │
│  例：前景理论、精英理论、路径依赖…         │
└─────────────────────────────────────────┘
```

| 层级 | 职责 | 用户心智 |
|------|------|----------|
| 场景 skill | 规定提问流程、输出结构、调用哪些 reference、反偏见检查点 | 「帮我做一件事」 |
| Reference | 单个理论/方法的定义、适用边界、常见误用、引导问题 | 「给我一块可引用的知识积木」 |

**否决倾向：** 仅五大巨型学科 skill（难贡献、难组合）；仅原子理论而无场景（难直接达成产品目标）。

## 6. 语言策略

| 层级 | 策略 |
|------|------|
| 网页 UI | 中 / 英切换 |
| Skill / reference 正文 | 以贡献者上传语言为准，不强制双语全文 |

## 7. 社区与仓库分层（B + D）

**B — 贡献路径**

- 合入真相源：**GitHub PR**  
- 网页：**贡献页**（规范说明、模板链接、Issue/PR 模板跳转）  
- v1 **不做**网页表单直传 + 自建审核后台  

**D — 目录分层**

| 分区 | 含义 | 合入门槛（原则） |
|------|------|------------------|
| `official/` | 核心维护、与产品叙事强绑定 | 较高：质量、风格、可引用性 |
| `community/` | 社区贡献 | 较低但仍需规范与基础审查 |

网页可筛选 official / community；展示质量/来源徽章。

## 11. Skill 热度 / 下载量（第三档）

**选择：** 同时记录 **网页侧行为** 与 **CLI 安装成功**，作为 skill 热度。

| 计入「安装热度」主指标 | 权重 / 说明 |
|------------------------|-------------|
| CLI `install` **成功写入** Agent 目录后 | **主计数**（+1 / skill / 成功安装事件） |
| 网页 **下载 zip / 打包下载** 成功发起 | **主计数**（与 CLI 同榜或分项展示 installs） |
| 网页 **复制安装命令** | **次级 / 低权重** 或不计入主榜（可记 `copy` 事件供漏斗，默认不驱动 `sort=popular`） |
| 仅打开详情页 | **不计入** 下载/安装热度（可另做 pageview，非 v1 必须） |

**原则：**

- **匿名**：只记 `skillId`、事件类型、日桶、可选粗粒度渠道（web|cli）；不登录、不存可识别个人信息  
- **可退出**：CLI 支持 `--no-telemetry` / 环境变量关闭；隐私说明写在 Docs/FAQ  
- **防误导**：展示优先 **近 30 天** + 累计；文案用「安装热度 / Installs」，避免与 GitHub Download 混淆  
- **排序**：默认仍 **featured**；用户可选 `sort=popular`  
- **数据位置**：热度 **不写进** `SKILL.md`；由统计服务维护，经 API/`stats` 合并进目录展示  
- **GitHub 直接 clone/raw**：v1 **不强求**计入（测不准）；以官网与官方 CLI 为准  

**否决：** 仅展示假热度、或 v1 完全不做计数（已升级为要做第三档）。

详细管道见知识库 [12-热度与遥测](./12-热度与遥测.md)。MCP 成功安装与 CLI 同事件名 `cli_install_success`，`source: "mcp"`。

## 18. Orientation 交接层（Handoff）— **D1**（2026-07-30）

**触发：** Reddit 反馈 — Recognition→Responsibility、责任域分层、分析闭合。  
**诊断：** 缺口真实且 on-mission；主战场是 **skill 内容 + 发现/安装**，不是新分析引擎。

### 决策 D1（采纳）

| 项 | 结论 |
|----|------|
| **Orientation core** | **保留**三大导向场景：`macro-scan` · `personal-anchor` · `metacognition-audit`。Home 主叙事仍以 triad 为主，**不**改写成「六大英雄」。 |
| **Handoff 层（3 官方 scenario）** | `responsibility-scope` · `responsibility-bridge` · `analysis-closure`（可 featured 第二行 / tag `orientation-pipeline`） |
| **否决默认** | **D2**（零新官方）作默认；**D3**（六场景品牌重写）本波不做。资源紧时 MVP 序：`analysis-closure` + `responsibility-scope` 优先，bridge 次之。 |

### CLI / MCP 硬边界

- **仍是技能包管理器 only**（search / list / get / install / update / detect）。  
- **明确不做：** `run` / analyze / 托管会话 / `recommend` / 教练式工具。  
- 责任判断与闭合只在**用户 Agent + `SKILL.md`**；装包 ≠ 编排分析。

### Catalog（可选、发现向）

- 可选 **`pipeline`** 元数据 + 官方 **`bundles`**（如 `orientation-handoff`），**仅**服务发现与组合安装。  
- **不**把 pipeline 当强制执行图；**不**用 `references[]` 编码场景下一步。  
- 旧 catalog 无新字段仍可 parse。

**实现权威：** [13-Orientation交接层](./13-Orientation交接层.md)。

## 22. 七科社科与教育学并列（SPE 34 · 2026-08-04）

**选择：** 将 **education（教育学 / Education）** 提升为与 psychology / sociology / history / political-science / economics / philosophy **同级** 的学科入口。

| 项 | 结论 |
|----|------|
| **产品统称** | **社科**（广义并列七科）；UI **不**再拆「核心五 / 扩展二」或给 education「次等」角标 |
| **固定七科 id**（排序建议） | `psychology` · `sociology` · `history` · `political-science` · `economics` · `philosophy` · **`education`** |
| **显示名** | 教育学 / Education；Home 短键 **`edu`** |
| **第一版（phase B）** | **可浏览**（Home 学科区 + Skills 七芯片 + URL `?discipline=education`）+ 存量 skill **双写**；**不**阻塞于 official education reference |
| **双写** | 跨域 pedagogy / 学习科学 skill 的 `disciplines` **多值追加** `education`（既有模式）；**17** 条 community scenarios 必双写；**排除** `social-stratification`（tag 的 education 是分层轴，非教育学入口） |
| **Official reference 分期** | education **≥3** 张 official reference 为路线图；philosophy 若仍无 official ref 同清单补齐。**诚实文案：** UI 七科 ≠ 七科均有 official 深度；当前 official 学科卡仍为 **五卡量级**（五社科），philosophy / education 可无 official ref 上架筛选 |
| **芯片色** | education `#3D7A6A`（生长绿；`DESIGN.md` / Overlay Atlas） |
| **收录边界** | 纳入学习科学、教法分析、`/teach` 型会话范式参考；**拒** exam-prep / 题库 / 区域课标教案工厂 / LMS 全栈 |
| **非目标（本版）** | 不交付 official education scenario；不批量导入外部 education skill 全集；不合并 history 与 education tab |

**否决/搁置：** 空壳宣称「每科均有 official reference 深度」；仅因正文出现「教育」一词就升 `disciplines: education`。

**实现权威：** 知识库 **08** / **09** / **10** · `PRODUCT.md` · `DESIGN.md`；执行规格历史见 `docs/specs/34-education-discipline-SPE.md`（蒸馏后以知识库为准）。
